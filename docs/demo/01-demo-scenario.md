# Demo Scenario

## Objective

Demonstrate that Loom can perform useful software-engineering work and retain the important knowledge from that work after the original session ends.

## Scenario

Use a small, real issue in the Loom repository. The issue should require enough investigation to produce meaningful context but be bounded enough to finish during a demonstration.

Example:

> Investigate a small bug or documentation/code-quality issue in Loom, determine the appropriate change, implement it, run the relevant tests, and explain the result.

The exact issue should be selected immediately before the demo so the repository state is current.

## Session 1

1. Start a local Loom runtime.
2. Start a new project/session for `FlossWare/loom-ai`.
3. Give Loom the selected GitHub issue.
4. Ask Loom to investigate before changing code.
5. Allow Loom to inspect relevant files and repository history.
6. Have Loom implement the change.
7. Run relevant tests.
8. Have Loom summarize:
   - problem
   - important discoveries
   - files changed
   - decision/reasoning
   - verification evidence
   - unresolved concerns
9. Persist the useful observations and decision information.
10. End the session.

## Session 2

Start a completely new session with no transcript from Session 1.

Ask:

> What did we learn while working on the previous issue, why did we make the change, and what evidence do we have that it works?

Loom should retrieve the relevant persistent knowledge and provide an answer with provenance.

Then ask a follow-up that requires the prior knowledge, for example:

> Given what we learned previously, what should we be careful about if we change this component again?

## Optional third step

Ask Loom to make a small follow-up change based on the remembered context.

This is the first real dogfood test: Loom is using knowledge generated by Loom to perform additional work on Loom.

## What the audience should see

The compelling moment is not merely that Loom can edit code. Other agents already do that.

The demonstration should make this obvious:

```text
Session 1
  investigate → implement → test → remember
                         ↓
                    Loom Knowledge
                         ↓
Session 2
  new process → retrieve → explain → continue
```

The important property is that the useful engineering knowledge survives the session boundary.
