## Overview

This document outlines the architecture for Loom-native agent context, memory, and workspace intelligence, specifically tailored for coding agents. The goal is to enable agents to build and maintain a relevant, explicit, and observable understanding of their coding environment without relying on external context management. This design emphasizes modularity, allowing for replaceable components that handle workspace interaction, task-specific state, and context assembly.

The core strategy involves defining specialized components for workspace discovery, project structure analysis, and task state management. These components will feed into a dedicated `CodingContextManager`, which orchestrates the selection and prioritization of information. This manager will then provide structured context elements to the existing generic `ContextAssembler` (from Phase 6), which is responsible for final context construction, budgeting, and compaction, ensuring efficient use of LLM context windows.

Key design principles include avoiding blind context stuffing, supporting incremental updates as the workspace evolves, preserving provenance for included information, and allowing optional integration with a Loom Knowledge Base. The architecture ensures that all context-related operations are explicit and observable, facilitating debugging and agent introspection.

## Protocols/Contracts

New protocols are defined to manage workspace interaction, task-specific state, and the orchestration of coding context. These protocols integrate with existing `ContextAssembler` (Phase 6) and `AgentMemory` (Phase 5) contracts.

```python
# loom_ai/contracts_coding.py
from __future__ import annotations

from typing import TYPE_CHECKING, Any, AsyncIterator, Protocol, runtime_checkable

if TYPE_CHECKING:
    from loom_ai.models_coding import (
        FileContent,
        FilePath,
        GitDiff,
        KnowledgeQueryResult,
        ProjectStructure,
        TaskState,
        WorkspaceSnapshot,
    )
    from loom_ai.models_phase6 import ContextSource # For integration


# -- Workspace Management ---------------------------------------------------


@runtime_checkable
class WorkspaceManager(Protocol):
    """Manages interaction with the agent's workspace (file system, project structure)."""

    async def get_workspace_snapshot(self, path: FilePath) -> WorkspaceSnapshot:
        """Returns a snapshot of the workspace at the given path."""
        ...

    async def get_project_structure(self, path: FilePath) -> ProjectStructure:
        """Analyzes and returns the project structure (e.g., file tree, module graph)."""
        ...

    async def get_file_content(self, path: FilePath) -> FileContent:
        """Retrieves the content of a specific file."""
        ...

    async def list_relevant_files(
        self, path: FilePath, query: str, max_files: int = 10
    ) -> AsyncIterator[FilePath]:
        """Identifies and yields paths to files relevant to a given query."""
        ...


# -- Task State Management --------------------------------------------------


@runtime_checkable
class TaskStateManager(Protocol):
    """Manages persistent and transient state related to a coding task."""

    async def get_task_state(self, task_id: str) -> TaskState:
        """Retrieves the current state for a given task ID."""
        ...

    async def update_task_state(self, task_id: str, state: TaskState) -> None:
        """Updates the state for a given task ID."""
        ...

    async def get_git_diff(self, path: FilePath, since_commit: str | None = None) -> GitDiff:
        """Retrieves git changes for the workspace or specific files."""
        ...

    async def get_build_history(self, path: FilePath, limit: int = 5) -> list[str]:
        """Retrieves recent build logs/results for the project."""
        ...


# -- Coding Context Management ----------------------------------------------


@runtime_checkable
class CodingContextManager(Protocol):
    """Orchestrates the assembly of coding-specific context elements for the generic ContextAssembler."""

    async def get_context_sources(
        self,
        workspace_path: FilePath,
        task_id: str,
        current_query: str,
    ) -> AsyncIterator[ContextSource]:
        """
        Identifies and yields relevant ContextSource objects (from Phase 6)
        based on workspace, task state, and current query.
        """
        ...

    async def update_internal_state(
        self,
        workspace_path: FilePath,
        task_id: str,
        changes: Any,  # e.g., file modifications, new test results
    ) -> None:
        """Updates internal context representation based on incremental changes."""
        ...


# -- Knowledge Base (Optional) ----------------------------------------------


@runtime_checkable
class KnowledgeBase(Protocol):
    """Provides semantic search and retrieval from a knowledge base."""

    async def query_knowledge_base(
        self, query: str, top_k: int = 5
    ) -> list[KnowledgeQueryResult]:
        """Queries the knowledge base for relevant information."""
        ...
```

## Data Models

These dataclasses define the structured data exchanged between the new components and the existing Loom framework.

```python
# loom_ai/models_coding.py
from __future__ import annotations

from dataclasses import dataclass, field
from typing import Any, Dict, List, Literal, Optional, Union

# Basic types
FilePath = str
FileContent = str
GitDiff = str  # For simplicity, raw diff string

@dataclass(frozen=True)
class WorkspaceSnapshot:
    """A snapshot of the workspace directory structure."""
    root_path: FilePath
    files: List[FilePath]
    directories: List[FilePath]

@dataclass(frozen=True)
class ProjectStructureNode:
    """Represents a node in the project's file/module structure."""
    name: str
    path: FilePath
    type: Literal["file", "directory", "module", "package"]
    children: List["ProjectStructureNode"] = field(default_factory=list)
    metadata: Dict[str, Any] = field(default_factory=dict) # e.g., language, dependencies

@dataclass(frozen=True)
class ProjectStructure:
    """The hierarchical structure of a project."""
    root: ProjectStructureNode

@dataclass(frozen=True)
class TaskState:
    """The current state of a coding task."""
    task_id: str
    status: str
    current_step: str
    scratchpad: Dict[str, Any] = field(default_factory=dict)
    git_changes: Optional[GitDiff] = None
    test_results: Optional[str] = None
    build_logs: Optional[str] = None
    # Add other task-specific state as needed

@dataclass(frozen=True)
class KnowledgeQueryResult:
    """A result from a knowledge base query."""
    content: str
    source_uri: str
    relevance_score: float
    metadata: Dict[str, Any] = field(default_factory=dict)

```

## In-Memory Implementation Strategy

For the initial implementation, simple in-memory backends will be provided for each new protocol. These will serve as functional prototypes and allow for rapid iteration and testing.

*   **`InMemoryWorkspaceManager`**:
    *   `get_workspace_snapshot`: Uses `os.walk` to list files and directories.
    *   `get_project_structure`: A basic implementation that builds a hierarchical `ProjectStructureNode` tree based on file paths.
    *   `get_file_content`: Reads file content directly from the local filesystem.
    *   `list_relevant_files`: Performs a simple keyword search within file paths and/or file contents (for small files) to identify "relevant" files.
*   **`InMemoryTaskStateManager`**:
    *   Uses a dictionary (`Dict[str, TaskState]`) to store task states, keyed by `task_id`.
    *   `get_git_diff`: Mocks git diffs or uses `subprocess` to run `git diff` in the workspace.
    *   `get_build_history`: Stores a list of mock build logs or simple strings.
*   **`InMemoryCodingContextManager`**:
    *   Holds references to an `InMemoryWorkspaceManager` and `InMemoryTaskStateManager`.
    *   `get_context_sources`: Orchestrates calls to the `WorkspaceManager` and `TaskStateManager` to gather information. It converts this raw information into `ContextSource` objects (from `loom_ai.models_phase6`) with appropriate provenance and freshness scores. For example, file contents become `ContextSource(content=file_content, metadata={'path': file_path, 'provenance': 'relevant_file_search'})`.
    *   `update_internal_state`: Updates internal caches or flags based on changes, potentially triggering re-evaluation of relevant files or task state.
*   **`InMemoryKnowledgeBase` (Optional)**:
    *   A simple dictionary or list of pre-defined documents.
    *   `query_knowledge_base`: Performs basic substring matching or a mock retrieval based on the query.

## Follow-up Implementation Tasks

1.  **Implement `InMemoryWorkspaceManager`**: Provide basic file system interaction and project structure analysis.
2.  **Implement `InMemoryTaskStateManager`**: Store task states in memory, mock git and build history.
3.  **Implement `InMemoryCodingContextManager`**: Orchestrate context assembly, converting data from `WorkspaceManager` and `TaskStateManager` into `ContextSource` objects for the generic `ContextAssembler`.
4.  **Integrate with `ContextAssembler`**: Ensure `CodingContextManager`'s `get_context_sources` output is compatible with `loom_ai.contracts_phase6.ContextAssembler.assemble_context`.
5.  **Basic Compaction Strategy**: Within `CodingContextManager`, define initial heuristics for prioritizing context elements before passing to `ContextAssembler` for token-based compaction.
6.  **Git Integration**: Enhance `InMemoryTaskStateManager` to interact with actual Git repositories for diffs and history.
7.  **Incremental Context Updates**: Refine `CodingContextManager.update_internal_state` to efficiently track and incorporate changes from the workspace (e.g., file modifications, new test results).
8.  **Knowledge Base Integration (Optional)**: Implement `InMemoryKnowledgeBase` and integrate its queries into `CodingContextManager`'s context assembly process.
9.  **Context Provenance and Freshness**: Refine how provenance and freshness scores are assigned to `ContextSource` objects.
