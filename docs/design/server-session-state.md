## 1. Overview

This design defines the architectural contracts for a **server-owned session model** where the server is the source of truth for all persistent state. Clients participate via ephemeral handles and propose mutations. The model strictly separates **private conversation context** (client-scoped, ephemeral draft state) from **shared facts/decisions** (server-persisted, promotable, and collaborative).

Key requirements addressed:
- **Protocols:** `@runtime_checkable` interfaces with `async` methods.
- **Models:** `@dataclass(frozen=True)` for immutability and hashability.
- **Lifecycle:** Creation, joining, reconnection, and teardown.
- **Memory:** Explicit separation of private context vs. shared state with promotion semantics.
- **Concurrency:** Vector clocks, conflict detection, and deterministic ordering.
- **Resilience:** Checkpoints and reconnect recovery.

## 2. Core Models

All models are frozen dataclasses to ensure immutability, facilitating safe passing across async boundaries and caching.

```python
import uuid
from dataclasses import dataclass, field
from enum import Enum
from typing import Any, Dict, List, Optional, Protocol, runtime_checkable, Union, Tuple
from datetime import datetime

# --- Identifiers ---

@dataclass(frozen=True)
class SessionId:
    id: uuid.UUID
    def __str__(self): return str(self.id)

@dataclass(frozen=True)
class ClientId:
    id: uuid.UUID
    def __str__(self): return str(self.id)

@dataclass(frozen=True)
class EntityId:
    """Generic ID for facts, decisions, or context blocks."""
    id: uuid.UUID
    session: SessionId
    def __str__(self): return f"{self.session}:{self.id}"

# --- Concurrency & Ordering ---

@dataclass(frozen=True)
class VectorClock:
    """
    Logical clock for causal ordering and conflict detection.
    Maps node IDs (e.g., ClientId or ServerId) to monotonically increasing counts.
    """
    nodes: Dict[str, int] = field(default_factory=dict)

    def increment(self, node_id: str) -> 'VectorClock':
        nodes = dict(self.nodes)
        nodes[node_id] = nodes.get(node_id, 0) + 1
        return VectorClock(nodes)

    def is_concurrent_with(self, other: 'VectorClock') -> bool:
        """Returns True if neither clock causally dominates the other."""
        this_gez = all(self.nodes.get(n, 0) >= other.nodes.get(n, 0) for n in set(self.nodes) | set(other.nodes))
        other_gez = all(other.nodes.get(n, 0) >= self.nodes.get(n, 0) for n in set(self.nodes) | set(other.nodes))
        return not (this_gez or other_gez)

# --- State Models ---

class SessionStatus(Enum):
    DRAFT = "draft"          # Private context only
    ACTIVE = "active"        # Shared state committed
    ARCHIVED = "archived"
    CLOSED = "closed"

@dataclass(frozen=True)
class SessionConfig:
    """Configuration passed during session creation."""
    session_type: str
    max_participants: int
    conflict_strategy: 'ConflictResolutionStrategy'
    metadata: Dict[str, Any] = field(default_factory=dict)

@dataclass(frozen=True)
class Checkpoint:
    """Immutable snapshot of session state."""
    id: uuid.UUID
    session: SessionId
    vector_clock: VectorClock
    timestamp: datetime
    description: Optional[str] = None

@dataclass(frozen=True)
class MemoryEntry:
    """Base record for memory storage."""
    id: EntityId
    content: Any
    vector_clock: VectorClock
    created_at: datetime
    origin: ClientId

    def __repr__(self): return f"Memory({self.id})[{self.vector_clock}]"

@dataclass(frozen=True)
class SharedFact(MemoryEntry):
    """
    Promoted state. Visible to all participants.
    Subject to conflict detection and ordering.
    """
    type: str = "fact"
    
@dataclass(frozen=True)
class Decision(MemoryEntry):
    """
    A structured decision derived from context or facts.
    Implies consensus or authoritative server action.
    """
    justification: str

# --- Result Models ---

@dataclass(frozen=True)
class MutationResult:
    accepted: bool
    new_vector_clock: VectorClock
    conflict: Optional['ConflictInfo'] = None
    applied_ids: List[EntityId] = field(default_factory=list)

@dataclass(frozen=True)
class ConflictInfo:
    competing_clocks: List[VectorClock]
    affected_ids: List[EntityId]
    resolution_required: bool
```

## 3. Protocols

Protocols use `@runtime_checkable` to allow implementation validation and `async` methods for non-blocking I/O.

### 3.1 Session Lifecycle Protocol

Manages session identity, creation, access, and reconnection.

```python
@runtime_checkable
class SessionLifecycleProtocol(Protocol):
    
    async def create_session(
        self, 
        owner: ClientId, 
        config: SessionConfig
    ) -> SessionHandle:
        """
        Creates a new server-owned session.
        Returns a handle for the owner.
        """
        ...

    async def join_session(
        self,

        client: ClientId

        """
        Joins an existing active session.
        Validates client permissions and returns a handle.
        """
        ...

    async def leave_session(self, handle: SessionHandle) -> None:
        """

        Flushes private context if configured; discards otherwise.
        """
        ...

        self, 
        handle: SessionHandle

        ...

        """
```

## 4. State Ownership Matrix

| State Entity | Ownership | Mutability | Visibility | Conflict Policy | Sync Behavior |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Conversation Context** | Client (Owner of Handle) | Client Append-only | Client Private | N/A (Per-client stream) | Stored server-side per client; purge on leave unless promoted. |
| **Shared Facts** | Server | Server (via Client proposals) | All Participants | Vector Clock Conflict Detection | Eventual Consistency; Server authoritative. |
| **Decisions** | Server | Server (via Client proposals) | All Participants | Vector Clock + Schema Validation | Stronger ordering; may block until resolved. |
| **Session Config** | Server | Admin/Owner Only | All Participants | Last Writer Wins (with audit) | Immutable after `ACTIVE` transition. |
| **Checkpoints** | Server | Server Only | All Participants | Immutable once created | On-demand restore affects shared state. |
| **Vector Clocks** | Server | Server (merges clocks) | Handler Local (on handle) | Server merges increments | Handle `current_clock` updated on every response. |

## 5. Design Details

### 5.1 Session Identity & Lifecycle
- **Server Ownership:** The `SessionId` is generated by the server. Clients cannot create sessions via local state; they must call `create_session`.
- **Handles:** A `SessionHandle` is an ephemeral object containing the client's view of the session, including their `current_clock`. It is invalidated on network drop until `reconnect` is called.
- **Join/Split:** Clients join via `join_session`. Private context is scoped to the `ClientId`; joining does not expose another client's private context.

### 5.2 Private vs. Shared Memory
- **Private Context:** Acts as a scratchpad/waterfall. `append_context` updates the client's private stream. This state is serialized to the server for persistence but is not indexed for shared queries.
- **Promotion:** The atomic bridge between private and shared. `promote_to_shared` takes a list of `context_ids`, validates the handle owns them, creates `SharedFact` records, increments the global session vector clock, and persists. This is the only way private state becomes globally visible.
- **Read Isolation:** `read_private_context` filters by `handle.client`. `read_shared_state` ignores privacy filters.

### 5.3 Checkpoints
- **Creation:** `create_checkpoint` captures the current `VectorClock` and state snapshot.
- **Restoration:** `restore_checkpoint` rewinds shared state to the checkpoint's clock. Private context is generally preserved (as it reflects active client thought), or optionally cleared based on config.
- **Anchoring:** Promotions can be anchored to a checkpoint for versioning facts relative to a stable baseline.

### 5.4 Concurrent Updates & Conflict Detection
- **Vector Clocks:** Every mutation carries a `VectorClock`. The server merges clocks.
- **Detection:** When `promote_to_shared` or `propose_decision` is called, the server compares the client's `VectorClock` in the request against the current state clock for the target entities.
  - If `is_concurrent_with` returns `True`, a `ConflictInfo` is generated.
  - Based on `SessionConfig.conflict_strategy`:
    - `LWW/FWW`: Server auto-resolves.
    - `KEEP_BOTH`: Server appends both (ID generation handles collision).
    - `REQUIRE_HUMAN`: Mutation is buffered; client receives `ConflictInfo`; must call `resolve_conflict`.
- **Optimistic Locking:** Handles are updated with new clocks. Subsequent writes with stale clocks are rejected immediately.

### 5.5 Event Ordering
- **Global Sequence:** Shared events are ordered by a hybrid of `VectorClock` dominance and `timestamp` for concurrent ties.
- **Causal Consistency:** Clients receive events in causal order. `read_shared_state` can pass `since_clock` to fetch only events causally following a specific point.
- **Private Ordering:** Private events are strictly append-only per client; no cross-client ordering required.

### 5.6 Reconnect Behavior
- **Heartbeat:** Handles should implement liveness. If dropped, `is_connected` becomes `False`.
- **Recovery:** `reconnect` restores the session.
  1. Client sends `SessionId`, `ClientId`, `LastVectorClock`.
  2. Server validates client still has access.
  3. Server computes `missed_events` where `event_clock` is concurrent or dominates `LastVectorClock`.
  4. Server returns `ReconnectResult`.
  5. Client updates local handle and reconciles UI.
- **Conflict on Reconnect:** If private context was modified locally offline (unsupported in this strict server-owned model, but if allowed via draft store), promotion on reconnect must trigger conflict detection based on the clock delta.

## 6. Implementation Guidelines

1.  **Protocol Adherence:** Implementations must pass `isinstance(obj, SessionLifecycleProtocol)`.
2.  **Immutability:** Never mutate `VectorClock` or `SessionHandle` in place. Return new instances.
3.  **Async Boundaries:** All protocol methods are `async`. Database operations and network calls must be non-blocking.
4.  **Error Handling:** Protocols should raise typed exceptions (e.g., `SessionNotFound`, `ConflictError`, `PermissionDenied`) rather than returning error codes.
5.  **Testing:** Mock implementations of protocols should be possible using `unittest.mock` or protocol-compatible fixtures.

```python
async def run_workflow(session_mgr: SessionLifecycleProtocol, mem_mgr: MemoryAccessProtocol):
    # 1. Create
    config = SessionConfig(
        session_type="analysis", 
        max_participants=5, 
        conflict_strategy=ConflictResolutionStrategy.REQUIRE_HUMAN
    )
    owner_handle = await session_mgr.create_session(ClientId(id=uuid.uuid4()), config)

    # 2. Add Private Context
    ctx_result = await mem_mgr.append_context(owner_handle, [{"text": "User thought: A implies B"}])
    context_id = ctx_result.applied_ids[0]

    # 3. Promote to Shared
    # This triggers conflict check against server state

    # 4. Read Shared
    facts = await mem_mgr.read_shared_state(owner_handle)
```
