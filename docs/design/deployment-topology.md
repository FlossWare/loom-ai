## 1. Overview

This document defines the structural contracts, state boundaries, and
reference in-memory implementations for Loom-AI's **local** and
**client/server** deployment modes.  The design decouples execution
semantics from transport so that the same protocols work whether the
engine runs embedded in a single process or across a network boundary.

Key requirements addressed:

- **Uniform contracts:** identical `@runtime_checkable` Protocol
  interfaces for local and remote modes.
- **Capability negotiation:** explicit handshake so client and server
  agree on supported features before any work begins.
- **Local mode:** no server process required -- everything runs
  in-process with zero network overhead.
- **Remote mode:** long-lived sessions with reconnect/resume, streaming,
  cancellation, and timeout semantics across the network boundary.
- **State ownership:** clear matrix defining what is client-local versus
  server-owned.
- **Multi-client:** multiple clients/sessions against a single server.
- **Shared memory path:** support for persistent session context and
  cross-session memory sharing.

## 4. Protocol Contracts

All protocols use `@runtime_checkable` for structural subtyping.  Every
method is `async`.  No imports beyond the standard library.

### 4.1 Capability Negotiation

```python
@runtime_checkable
class CapabilityNegotiationProtocol(Protocol):
    """Handshake protocol for agreeing on transport and features."""

    async def negotiate(
        self,
        client_capabilities: ClientCapabilities,
    ) -> NegotiationResult:
        """Perform initial negotiation.

        The server inspects the client's advertised capabilities,
        intersects them with its own, and returns the agreed-upon
        feature set.
        """
        ...

    async def renegotiate(
        self,
        session_id: str,
        client_capabilities: ClientCapabilities,
    ) -> NegotiationResult:
        """Re-negotiate capabilities on an existing session.

        Used when the client or server gains new capabilities at
        runtime (e.g., a plugin is loaded).
        """
        ...
```

### 4.2 Session Management

```python
@runtime_checkable
class SessionProtocol(Protocol):
    """Session lifecycle: connect, disconnect, reconnect, resume."""

    async def connect(
        self,
        config: DeploymentConfig,
        client_capabilities: ClientCapabilities,
        *,
        auth_token: AuthToken | None = None,
    ) -> SessionHandle:
        """Establish a new session.

        Performs capability negotiation, authenticates if required,
        and returns an opaque session handle.
        """
        ...

    async def disconnect(self, session_id: str) -> None:
        """Graceful disconnect.  Server retains session state for the
        reconnect window defined in ``DeploymentConfig``."""
        ...

    async def reconnect(
        self,
        resume_token: SessionResumeToken,
        *,
        auth_token: AuthToken | None = None,
    ) -> SessionHandle:
        """Reconnect to an existing session using a resume token.

        The server replays any messages sent after the client's last
        acknowledged sequence number.
        """
        ...

    async def resume(
        self,
        session_id: str,
        last_sequence: int,
    ) -> SessionResumeToken:
        """Request a resume token for later reconnection.

        The token captures the session's current sequence position
        so the server knows where to start replaying.
        """
        ...

    async def send(
        self,
        session_id: str,
        message: TransportMessage,
    ) -> TransportMessage:
        """Send a message and receive a response.

        For non-streaming calls, the response is the complete reply.
        For streaming, use ``StreamingProtocol.stream_send`` instead.
        """
        ...

    async def receive(
        self,
        session_id: str,
        *,
        timeout_seconds: float = 30.0,
    ) -> TransportMessage:
        """Wait for a server-initiated message (push notification,
        event, or streamed chunk)."""
        ...
```

## 5. State Ownership Matrix

The following table defines which component owns each piece of state and
how it is synchronized between client and server.

| Component | Local Mode Owner | Server Mode Owner | Sync Strategy |
|---|---|---|---|
| Session lifecycle | Client (in-process) | Server | Create/join/leave RPCs |
| Conversation context | Client | Client (ephemeral) | Not synced -- private |
| Knowledge graph | Client (in-process) | Server | Mutations via RPC |
| Shared facts/decisions | Client (in-process) | Server | Promote RPC + vector clock |
| Model routing state | Client (in-process) | Server | Server-authoritative |
| Capability registry | Client (in-process) | Server | Negotiation handshake |
| Auth tokens | Client | Client | Passed per-request |
| Workspace identity | Client (self-issued) | Server | Validated on connect |
| Stream cursor | Client | Server | Sequence numbers |
| Resume tokens | N/A | Server (issued) | Client stores, server validates |
| Shared memory | Client (dict) | Server (broadcast) | Publish/subscribe |
| Configuration | Client (file/env) | Server (authoritative) | Sent during negotiation |
| Execution logs | Client (local) | Server | Append-only upload |
| Cost tracking | Client (local) | Server | Periodic flush |

**Key invariants:**

1. In **local mode**, the client owns everything -- there is no
   server process.  All protocols resolve to in-process calls.
2. In **client/server mode**, the server is the source of truth for
   persistent state.  The client holds only ephemeral conversation
   context and auth tokens.
3. **Hybrid mode** starts local and optionally connects to a server
   for shared memory, knowledge graph, and model routing.  The client
   can fall back to local if the server is unreachable.

## 6. Capability Negotiation Flow

```
Client                                 Server
  |                                      |
  |  1. ClientCapabilities               |
  |  ─────────────────────────────────>  |
  |                                      |
  |     (intersect with ServerCaps)      |
  |                                      |
  |  2. NegotiationResult                |
  |  <─────────────────────────────────  |
  |                                      |
  |  3. Open transport (agreed kind)     |
  |  ─────────────────────────────────>  |
  |                                      |
  |  4. SessionHandle                    |
  |  <─────────────────────────────────  |
  |                                      |
  |  [session active]                    |
  |                                      |
  |  5a. send / stream_send             |
  |  ─────────────────────────────────>  |
  |  5b. TransportMessage / StreamChunk  |
  |  <─────────────────────────────────  |
  |                                      |
  |  6. disconnect                       |
  |  ─────────────────────────────────>  |
  |                                      |
  |  [reconnect window open]             |
  |                                      |
  |  7. reconnect(resume_token)          |
  |  ─────────────────────────────────>  |
  |  8. SessionHandle (resumed)          |
  |  <─────────────────────────────────  |
```

**Step details:**

1. Client sends `ClientCapabilities` declaring its preferred transport,
   protocol version, and feature flags.
2. Server intersects with its own `ServerCapabilities`, selects the best
   compatible transport and version, and returns a `NegotiationResult`.
3. Client opens the agreed transport (e.g., TCP socket to the
   server's port).
4. Server creates a session and returns a `SessionHandle`.
5. Normal request/response or streaming communication.
6. Client disconnects gracefully.  Server keeps session state for the
   configured reconnect window.
7. Client reconnects with a `SessionResumeToken`.
8. Server replays any missed messages and returns a new handle.

## 7. Transport Layer

### 7.1 In-Process Transport

Used in **local mode**.  Calls are direct function invocations -- no
serialization, no network overhead.

### 7.2 Unix Socket Transport

Best for co-located client and server on the same host.  Lower latency
than TCP, no TLS overhead for local connections.

### 7.3 TCP Transport

Standard remote transport.  Supports TLS for encrypted connections.

### 7.4 WebSocket Transport

Enables browser-based clients and bidirectional streaming.  Built on
top of TCP with HTTP upgrade handshake.

### 7.5 Connection Lifecycle

All transports follow the same lifecycle:

1. `open(config)` -- establish the connection.
2. `send_bytes(data)` / `receive_bytes()` -- exchange data.
3. `close()` -- tear down the connection.

### 7.6 Reconnection with Exponential Backoff

When a transport disconnects unexpectedly, the client retries with
exponential backoff:

```python
import asyncio
import random


async def reconnect_with_backoff(
    transport: TransportProtocol,
    config: DeploymentConfig,
) -> None:
    """Reconnect with exponential backoff and jitter."""
    attempt = 0
    while attempt < config.max_reconnect_attempts:
        delay = min(
            config.backoff_base_seconds * (2 ** attempt),
            config.backoff_max_seconds,
        )
        jitter = random.uniform(0, delay * 0.1)
        await asyncio.sleep(delay + jitter)
        try:
            await transport.open(config)
            return
        except OSError:
            attempt += 1
    raise ConnectionError(
        f"Failed to reconnect after {config.max_reconnect_attempts} attempts"
    )
```

## 8. Session Management

### 8.1 Session Creation

A new session is created when `SessionProtocol.connect()` is called.
The server:

1. Validates the auth token (if `auth_scheme != NONE`).
2. Runs capability negotiation.
3. Allocates a session slot (bounded by `max_sessions`).
4. Returns a `SessionHandle`.

### 8.2 Reconnection

If the client disconnects (network failure, process restart), it can
reconnect within the `reconnect_window_seconds` using a
`SessionResumeToken`.  The server:

1. Validates the resume token (session ID, checksum, expiry).
2. Replays any messages sent after the client's `last_sequence`.
3. Returns a new `SessionHandle` with the same `session_id`.

### 8.3 Multi-Client Support

Multiple clients can connect to the same server simultaneously.  Each
gets its own `SessionHandle` and conversation context.  Shared state
(knowledge graph, facts, decisions) is accessible to all clients within
the same workspace, mediated by the `SharedMemoryBridge`.

| Aspect | Single-Client | Multi-Client |
|---|---|---|
| Session isolation | Full | Per-session context |
| Knowledge graph | Exclusive | Shared via server |
| Shared memory | N/A | Publish/subscribe |
| Conflict resolution | N/A | Vector clocks |

## 9. Authentication & Authorization

### 9.1 Token-Based Auth

Clients authenticate by passing an `AuthToken` during `connect()`.
The server validates the token and returns a `WorkspaceIdentity`.

### 9.2 Workspace Identity

A `WorkspaceIdentity` scopes all operations to a workspace.  Project
boundaries within a workspace further restrict what resources a client
can access.

### 9.3 Local Mode Auth

In local mode, authentication is optional.  A self-issued
`WorkspaceIdentity` with a default workspace ID is used.

## 10. Streaming, Cancellation, and Timeouts

### 10.1 Streaming

The `StreamingProtocol` enables chunked responses.  Each `StreamChunk`
carries a sequence number for ordering and a `is_final` flag to signal
completion.  Chunks are delivered in order per session.

### 10.2 Cooperative Cancellation

A `CancellationToken` is passed to `stream_send()`.  Either side can
set `cancelled=True`.  The producer SHOULD stop within one chunk cycle.
The consumer calls `cancel_stream()` to notify the server.

### 10.3 Timeout Semantics

- **Transport timeout:** `receive_bytes(timeout_seconds=...)` on the
  transport layer.  Raises `TimeoutError`.
- **Session timeout:** `session_timeout_seconds` in `DeploymentConfig`.
  The server closes idle sessions after this duration.
- **Request timeout:** `receive(timeout_seconds=...)` on the session
  layer.  Raises `TimeoutError` if no response arrives.

## 11. Failure Semantics

### 11.1 Network Partition

When the transport detects a disconnect:

1. Client enters **reconnecting** state.
2. Client retries with exponential backoff (section 7.6).
3. If reconnection succeeds within the window, the session resumes.
4. If the window expires, the session is closed and the client must
   create a new one.

### 11.2 Graceful Degradation (Hybrid Mode)

In hybrid mode, if the server becomes unreachable:

1. Client falls back to local-only operation.
2. Mutations are queued locally.
3. When the server is reachable again, queued mutations are replayed.
4. Conflicts are resolved using the configured strategy.

### 11.3 Circuit Breaker

A circuit breaker protects the client from repeatedly hitting a
down server:

```python
@dataclass
class CircuitBreaker:
    """Simple circuit breaker for transport connections."""

    failure_threshold: int = 5
    reset_timeout_seconds: float = 60.0
    _failure_count: int = 0
    _state: str = "closed"  # closed, open, half_open
    _last_failure_time: float = 0.0

    def record_failure(self, now: float) -> None:
        self._failure_count += 1
        self._last_failure_time = now
        if self._failure_count >= self.failure_threshold:
            self._state = "open"

    def record_success(self) -> None:
        self._failure_count = 0
        self._state = "closed"

    def allow_request(self, now: float) -> bool:
        if self._state == "closed":
            return True
        if self._state == "open":
            if now - self._last_failure_time >= self.reset_timeout_seconds:
                self._state = "half_open"
                return True
            return False
        return True  # half_open: allow one probe
```

## 12. InMemory Reference Implementations

These are zero-dependency implementations for testing and local mode.
They follow the same patterns as other loom-ai `InMemory*` backends.

### 12.1 InMemoryTransport

```python
import asyncio
from collections import deque


class InMemoryTransport:
    """In-process transport -- direct function calls, no network."""

    def __init__(self) -> None:
        self._connected = False
        self._inbox: deque[bytes] = deque()

    async def open(self, config: DeploymentConfig) -> None:
        self._connected = True

    async def close(self) -> None:
        self._connected = False
        self._inbox.clear()

    async def send_bytes(self, data: bytes) -> None:
        if not self._connected:
            raise ConnectionError("transport not connected")
        self._inbox.append(data)

    async def receive_bytes(
        self,
        *,
        timeout_seconds: float = 30.0,
    ) -> bytes:
        if not self._connected:
            raise ConnectionError("transport not connected")
        deadline = asyncio.get_event_loop().time() + timeout_seconds
        while not self._inbox:
            if asyncio.get_event_loop().time() >= deadline:
                raise TimeoutError("receive timed out")
            await asyncio.sleep(0.01)
        return self._inbox.popleft()

    async def is_connected(self) -> bool:
        return self._connected
```

### 12.2 InMemorySession

```python
class InMemorySession:
    """In-memory session manager for local and testing use."""

    def __init__(self) -> None:
        self._sessions: dict[str, SessionHandle] = {}
        self._sequences: dict[str, int] = {}
        self._messages: dict[str, list[TransportMessage]] = {}

    async def connect(
        self,
        config: DeploymentConfig,
        client_capabilities: ClientCapabilities,
        *,
        auth_token: AuthToken | None = None,
    ) -> SessionHandle:
        server_caps = ServerCapabilities()
        agreed_version = (
            client_capabilities.protocol_version
            if client_capabilities.protocol_version
            in server_caps.protocol_versions
            else server_caps.protocol_versions[-1]
        )
        negotiation = NegotiationResult(
            agreed_version=agreed_version,
            transport=client_capabilities.preferred_transport,
            streaming_enabled=(
                client_capabilities.streaming and server_caps.streaming
            ),
            cancellation_enabled=(
                client_capabilities.cancellation
                and server_caps.cancellation
            ),
            shared_memory_enabled=server_caps.shared_memory,
            server_capabilities=server_caps,
            client_capabilities=client_capabilities,
        )
        handle = SessionHandle(
            session_id=negotiation.session_id,
            client_id=str(uuid.uuid4()),
            deployment_mode=config.mode,
            negotiation=negotiation,
        )
        self._sessions[handle.session_id] = handle
        self._sequences[handle.session_id] = 0
        self._messages[handle.session_id] = []
        return handle

    async def disconnect(self, session_id: str) -> None:
        pass  # retain state for reconnect window

    async def reconnect(
        self,
        resume_token: SessionResumeToken,
        *,
        auth_token: AuthToken | None = None,
    ) -> SessionHandle:
        handle = self._sessions.get(resume_token.session_id)
        if handle is None:
            raise ConnectionError("session expired or unknown")
        return handle

    async def resume(
        self,
        session_id: str,
        last_sequence: int,
    ) -> SessionResumeToken:
        return SessionResumeToken(
            session_id=session_id,
            sequence_number=last_sequence,
            checksum="",
        )

    async def send(
        self,
        session_id: str,
        message: TransportMessage,
    ) -> TransportMessage:
        seq = self._sequences.get(session_id, 0) + 1
        self._sequences[session_id] = seq
        self._messages.setdefault(session_id, []).append(message)
        return TransportMessage(
            session_id=session_id,
            payload=b"ack",
            sequence=seq,
            is_final=True,
        )

    async def receive(
        self,
        session_id: str,
        *,
        timeout_seconds: float = 30.0,
    ) -> TransportMessage:
        msgs = self._messages.get(session_id, [])
        if msgs:
            return msgs[-1]
        raise TimeoutError("no messages available")
```

```python
    def __init__(self) -> None:
        self._config: DeploymentConfig | None = None
        self._session_manager = InMemorySession()
        self._running = False

    async def start(self, config: DeploymentConfig) -> None:
        self._config = config
        self._running = True

    async def stop(self) -> None:
        self._running = False

    async def health_check(self) -> HealthStatus:
        return HealthStatus(
            healthy=self._running,
            mode=(
                self._config.mode
                if self._config
                else DeploymentMode.LOCAL
            ),
            active_sessions=len(
                self._session_manager._sessions
            ),
        )

    async def list_sessions(self) -> Sequence[SessionHandle]:
        return list(self._session_manager._sessions.values())

    async def get_session(
        self, session_id: str
    ) -> SessionHandle | None:
        return self._session_manager._sessions.get(session_id)
```

### 12.4 InMemorySharedMemoryBridge

```python
class InMemorySharedMemoryBridge:
    """In-memory shared memory for co-located sessions."""

    def __init__(self) -> None:
        self._store: dict[str, dict[str, Any]] = {}

    async def publish(
        self,
        session_id: str,
        key: str,
        value: Any,
        *,
        scope: str = "workspace",
    ) -> None:
        self._store.setdefault(scope, {})[key] = value

    async def subscribe(
        self,
        session_id: str,
        key: str,
        *,
        scope: str = "workspace",
    ) -> Any:
        return self._store.get(scope, {}).get(key)

    async def list_keys(
        self,
        *,
        scope: str = "workspace",
    ) -> Sequence[str]:
        return list(self._store.get(scope, {}).keys())

    async def delete(
        self,
        session_id: str,
        key: str,
        *,
        scope: str = "workspace",
    ) -> None:
        self._store.get(scope, {}).pop(key, None)
```

## 15. Decision Log

| # | Decision | Rationale | Alternatives Considered |
|---|---|---|---|
| 1 | Protocol-based contracts (not ABC) | Structural subtyping matches loom-ai patterns; no inheritance coupling | ABC with mixins |
| 2 | Frozen dataclasses for all models | Immutability, hashability, safe across async boundaries | Mutable dataclasses, TypedDict |
| 3 | Separate transport from session | Transport is byte-level plumbing; session is semantic | Combined session+transport |
| 4 | Exponential backoff with jitter | Prevents thundering herd on server recovery | Fixed delay, linear backoff |
| 5 | Resume tokens over session cookies | Tokens are opaque and stateless on the client; server validates | Cookie-based, session ID reuse |
| 6 | Circuit breaker at client level | Protects client from hammering a down server | Server-side rate limiting only |
| 7 | Hybrid mode as first-class variant | Enables offline-first with optional cloud sync | Local-only + separate remote mode |
| 8 | Shared memory via publish/subscribe | Decouples producers from consumers; scales to N clients | Direct memory sharing, RPC |
| 9 | Vector clocks for conflict detection | Causal ordering without centralized sequencer | Lamport timestamps, CRDTs |
| 10 | In-memory implementations for all protocols | Zero-dependency testing and local mode; matches existing pattern | Mock-only testing |
