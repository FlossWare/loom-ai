## Overview

This document outlines the architecture and design for a Loom-native agent runtime, focusing on enabling a robust coding-agent experience. The goal is to establish Loom's own agent/runtime semantics, capable of orchestrating model interactions, tool execution, context management, and state persistence, while treating external coding agents (e.g., Crush, OpenCode, Aider) as optional, pluggable adapters or delegated workers. This approach ensures Loom's core remains independent and extensible.

The architecture centers around a contract-driven design, leveraging existing Loom protocols where possible and introducing new ones to cover interactive sessions, tool orchestration, policy enforcement, and verification loops. The Loom Agent Runtime will serve as the central orchestrator, integrating components for model inference, context assembly, tool management, and secure environment interaction.

This design establishes clear boundaries between the agent's core logic, its interaction with models and tools, and its operational environment. It defines the necessary protocols and data models for a durable, interactive, and verifiable agent experience, laying the groundwork for a secure and adaptable coding assistant within the Loom ecosystem.

## Key Protocols/Contracts

The Loom-native agent runtime will reuse several existing `loom-ai` contracts and introduce new ones to address the specific requirements of an interactive coding agent.

**Reused Contracts (from `contracts_inference.py` and `contracts_agent.py`):**

*   **`AgentLoop`**: Orchestrates the agent's turn-based state machine, including pause/resume/cancel semantics.
*   **`InferenceRouter`**: Handles model provider selection, inference requests, and adaptive routing.
*   **`AgentMemory`**: Provides persistent, scoped, and typed memory for agent state.
*   **`OutputValidator`**: Validates tool outputs and model responses against schemas.
*   **`ContextAssembler`**: Manages context construction, budgeting, and compaction for model prompts.
*   **`AgentEnvironment`**: Provides an interface for interacting with the execution environment (e.g., filesystem, shell, git).
*   **`AgentCapabilityRegistry`**: Catalogs and matches agent/model capabilities with requirements.

**New Contracts (to be defined in `contracts_provider.py`):**

*   **`AgentSession`**: Manages the lifecycle, state, and history of an interactive agent session.
*   **`ToolExecutor`**: Selects, executes, and manages the results of various tools, including delegation to external agents/adapters.
*   **`PolicyEnforcer`**: Enforces security, permissions, and approval policies for sensitive operations.
*   **`VerificationLoop`**: Manages automated verification, self-correction, and retry mechanisms.
*   **`HumanInteraction`**: Facilitates human-readable CLI interaction, prompts, and approvals.

## Concrete Protocol Definitions

```python
# loom_ai/contracts_provider.py
from __future__ import annotations

from typing import TYPE_CHECKING, Any, Literal, Protocol, runtime_checkable

if TYPE_CHECKING:
    from loom_ai.models_agent import (
        AgentOperation,
        AgentState,
        AgentTurn,
        EnvironmentSpec,
        AgentEnvironmentObservation,
    )
    from loom_ai.models_provider import (
        AgentSessionState,
        ToolInvocation,
        ToolResult,
        PolicyDecision,
        VerificationResult,
        HumanInput,
        HumanResponse,
    )


@runtime_checkable
class AgentSession(Protocol):
    """Manages the lifecycle and durable state of an interactive agent session."""

    async def create_session(self, initial_state: AgentSessionState) -> str:
        """Initializes a new agent session and returns its unique ID."""
        ...

    async def get_session_state(self, session_id: str) -> AgentSessionState:
        """Retrieves the current durable state of a session."""
        ...

    async def update_session_state(self, session_id: str, new_state: AgentSessionState) -> None:
        """Updates the durable state of an existing session."""
        ...

    async def end_session(self, session_id: str, status: Literal["completed", "failed", "cancelled"]) -> None:
        """Terminates an agent session with a final status."""
        ...

    async def get_session_history(self, session_id: str, limit: int | None = None) -> list[AgentTurn]:
        """Retrieves the history of agent turns for a session."""
        ...


@runtime_checkable
class ToolExecutor(Protocol):
    """Orchestrates tool selection, execution, and result handling, including delegation."""

    async def select_tool(self, agent_state: AgentState, available_tools: list[str]) -> ToolInvocation:
        """Selects the appropriate tool and generates its invocation parameters."""
        ...

    async def execute_tool(self, invocation: ToolInvocation) -> ToolResult:
        """Executes a tool invocation, potentially delegating to an adapter."""
        ...

    async def register_tool(self, tool_name: str, tool_spec: Any) -> None:
        """Registers a new tool or tool adapter with the executor."""
        ...

    async def get_tool_spec(self, tool_name: str) -> Any:
        """Retrieves the specification for a registered tool."""
        ...


@runtime_checkable
class PolicyEnforcer(Protocol):
    """Enforces security, permissions, and approval policies for sensitive operations."""

    async def check_permission(self, operation: AgentOperation, context: dict[str, Any]) -> PolicyDecision:
        """Checks if an operation is permitted based on current policies."""
        ...

    async def request_approval(self, operation: AgentOperation, prompt: str) -> PolicyDecision:
        """Requests human approval for a sensitive operation."""
        ...


@runtime_checkable
class VerificationLoop(Protocol):
    """Manages automated verification, self-correction, and retry mechanisms."""

    async def verify_output(self, operation: AgentOperation, output: Any) -> VerificationResult:
        """Verifies the output of an operation against expected criteria."""
        ...

    async def suggest_correction(self, operation: AgentOperation, feedback: str) -> AgentOperation:
        """Generates a suggested correction for a failed operation."""
        ...


@runtime_checkable
class HumanInteraction(Protocol):
    """Facilitates human-readable CLI interaction, prompts, and approvals."""

    async def display_message(self, message: str, level: Literal["info", "warning", "error"] = "info") -> None:
        """Displays a message to the user."""
        ...

    async def prompt_user(self, prompt: HumanInput) -> HumanResponse:
        """Prompts the user for input or approval."""
        ...
```

## Data Models

```python
# loom_ai/models_provider.py
from __future__ import annotations

from dataclasses import dataclass, field
from typing import Any, Literal

if TYPE_CHECKING:
    from loom_ai.models_agent import AgentState, AgentTurn


@dataclass(frozen=True)
class AgentSessionState:
    """Represents the durable state of an agent session."""
    session_id: str
    agent_state: AgentState  # Reuses existing AgentState
    history: list[AgentTurn] = field(default_factory=list)  # Reuses existing AgentTurn
    current_task: str = ""
    status: Literal["active", "paused", "completed", "failed", "cancelled"] = "active"
    metadata: dict[str, Any] = field(default_factory=dict)


@dataclass(frozen=True)
class ToolInvocation:
    """Represents a request to execute a specific tool."""
    tool_name: str
    args: dict[str, Any]
    invocation_id: str
    context: dict[str, Any] = field(default_factory=dict)
    delegated_to: str | None = None # For external agent/adapter delegation


@dataclass(frozen=True)
class ToolResult:
    """Represents the outcome of a tool execution."""
    invocation_id: str
    status: Literal["success", "failure", "timeout", "pending_approval"]
    output: Any | None = None
    error_message: str | None = None
    logs: list[str] = field(default_factory=list)


@dataclass(frozen=True)
class PolicyDecision:
    """Represents a decision made by the PolicyEnforcer."""
    approved: bool
    reason: str = "Approved by policy."
    requires_human_approval: bool = False


@dataclass(frozen=True)
class VerificationResult:
    """Represents the outcome of a verification step."""
    success: bool
    feedback: str = ""
    suggested_changes: list[AgentOperation] = field(default_factory=list)


@dataclass(frozen=True)
class HumanInput:
    """Represents a prompt for human interaction."""
    prompt_text: str
    input_type: Literal["text", "boolean", "choice", "approval"] = "text"
    options: list[str] | None = None
    default_value: str | bool | None = None


@dataclass(frozen=True)
class HumanResponse:
    """Represents a response received from human interaction."""
    response_value: str | bool
    timestamp: float
```

## In-memory Implementation Strategy

For initial development and testing, in-memory backends will provide simple, non-persistent implementations of the new protocols. These will reside in `loom_ai/backends/in_memory/`.

*   **`InMemoryAgentSession`**: Will use a dictionary (`Dict[str, AgentSessionState]`) to store session states, keyed by `session_id`. History will be appended to the `history` list within `AgentSessionState`.
*   **`InMemoryToolExecutor`**: Will maintain a dictionary of registered tool specifications (`Dict[str, Any]`) and a simple dispatch mechanism. For `execute_tool`, it will contain mock implementations or direct calls to simple, in-memory "tool functions" (e.g., a mock `GitTool` that simulates file changes). Delegation to external agents will be simulated by logging the delegation attempt.
*   **`InMemoryPolicyEnforcer`**: Will implement basic, hardcoded rules (e.g., "all filesystem writes require approval", "read operations are always permitted"). `request_approval` will simply return `PolicyDecision(approved=True)` or `False` based on a configurable flag, without actual human interaction.
*   **`InMemoryVerificationLoop`**: Will have a configurable success rate or simple rule-based verification (e.g., "if output contains 'error', then fail"). `suggest_correction` will return a predefined mock `AgentOperation`.
*   **`CLIHumaInteraction`**: Will use `print()` for `display_message` and `input()` for `prompt_user`, providing a basic command-line interface for human interaction.

## Follow-up Implementation Tasks

1.  **Implement `InMemoryAgentSession`**: Create the in-memory backend for session management.
2.  **Implement `InMemoryToolExecutor`**: Develop the in-memory tool executor, including a basic registry and mock execution for common coding tools (e.g., `FileReadTool`, `FileWriteTool`, `ShellCommandTool`).
3.  **Implement `InMemoryPolicyEnforcer`**: Create a basic in-memory policy enforcer with configurable rules.
4.  **Implement `InMemoryVerificationLoop`**: Develop a simple in-memory verification loop with mock correction suggestions.
5.  **Implement `CLIHumaInteraction`**: Create the command-line interface for human interaction and approvals.
6.  **Integrate `AgentEnvironment`**: Ensure the `AgentEnvironment` contract is fully utilized by the `ToolExecutor` for actual filesystem, shell, and git operations.
7.  **Develop Core Coding Tools**: Implement concrete `ToolExecutor` compatible tools for:
    *   Filesystem operations (read, write, list, delete).
    *   Shell command execution.
    *   Git operations (clone, commit, diff, branch).
    *   Test/build execution (e.g., `pytest`, `make`).
8.  **Build Agent Runtime Orchestrator**: Develop the main runtime logic that integrates `AgentLoop`, `AgentSession`, `InferenceRouter`, `ToolExecutor`, `ContextAssembler`, `PolicyEnforcer`, `VerificationLoop`, and `HumanInteraction`.
9.  **Develop Example Coding Agent Profile**: Define an initial `AgentState` and `AgentOperation` sequence for a simple coding task (e.g., "fix a bug in a Python file").
10. **Create External Agent Adapters (Example)**: Implement a mock `CrushAdapter` or `OpenCodeAdapter` that registers with `ToolExecutor` and simulates delegation.
11. **Security Review**: Conduct an initial security review for shell/filesystem/git operations, focusing on sandboxing and permission models.
