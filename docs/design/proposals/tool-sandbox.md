# Design: Tool Capability Model and Sandbox

## Overview

This document outlines the architecture and design for a Loom-native coding tool capability model and execution sandbox. The goal is to provide a stable, declarative interface for agents to interact with a development environment, abstracting away underlying tool implementations like Crush, OpenCode, or Aider. This design emphasizes structured results, robust error handling, and a secure execution environment.

The core of this design involves defining a set of Python Protocols for common coding operations, along with corresponding data models for inputs, outputs, and configuration. These protocols will enable Loom agents to reason over well-defined capabilities, while the execution sandbox ensures operations adhere to specified permissions, resource limits, and workspace boundaries. This approach facilitates interoperability, testability, and the integration of diverse tool backends.

The initial set of capabilities covers fundamental development tasks including filesystem manipulation, shell command execution, Git operations, build/test execution, environment inspection, and optional web access. Each capability will have a dedicated Loom contract, ensuring a consistent and type-safe interaction model for agents.

## Key Protocols/Contracts

The following protocols define the stable Loom contracts for coding tool capabilities. All methods are asynchronous and designed to return structured data or raise structured errors.

```python
# loom_ai/contracts_provider.py
from __future__ import annotations

from typing import TYPE_CHECKING, Any, Protocol, runtime_checkable
from pathlib import Path
from datetime import datetime

if TYPE_CHECKING:
    from loom_ai.models_provider import (
        ToolExecutionConfig, ToolResult, ToolError, FileContent, FileInfo, TextEdit,
        ShellOutput, GitStatus, GitDiff, GitLog, BuildOutput, TestOutput,
        EnvironmentInfo, WebContent, SearchResult,
    )


@runtime_checkable
class FileSystemTool(Protocol):
    """Provides capabilities for interacting with the filesystem."""

    async def read_file(self, path: Path, config: ToolExecutionConfig) -> FileContent:
        """Reads the content of a file."""
        ...

    async def write_file(self, path: Path, content: str, config: ToolExecutionConfig) -> ToolResult:
        """Writes content to a file, overwriting if it exists."""
        ...

    async def edit_file(self, path: Path, edits: list[TextEdit], config: ToolExecutionConfig) -> ToolResult:
        """Applies a list of text edits to a file."""
        ...

    async def list_directory(self, path: Path, config: ToolExecutionConfig) -> list[FileInfo]:
        """Lists contents of a directory."""
        ...

    async def search_files(self, pattern: str, config: ToolExecutionConfig) -> list[Path]:
        """Searches for files matching a glob pattern."""
        ...


@runtime_checkable
class ShellTool(Protocol):
    """Provides capabilities for executing shell commands."""

    async def execute_command(self, command: str, args: list[str], config: ToolExecutionConfig) -> ShellOutput:
        """Executes a shell command with arguments."""
        ...


@runtime_checkable
class GitTool(Protocol):
    """Provides capabilities for Git repository operations."""

    async def get_status(self, config: ToolExecutionConfig) -> GitStatus:
        """Retrieves the current Git status."""
        ...

    async def get_diff(self, config: ToolExecutionConfig) -> GitDiff:
        """Retrieves the Git diff for the current changes."""
        ...

    async def get_log(self, config: ToolExecutionConfig) -> GitLog:
        """Retrieves the Git commit log."""
        ...

    async def create_branch(self, branch_name: str, config: ToolExecutionConfig) -> ToolResult:
        """Creates a new Git branch."""
        ...

    async def commit(self, message: str, config: ToolExecutionConfig) -> ToolResult:
        """Commits current changes to the repository."""
        ...


@runtime_checkable
class BuildTool(Protocol):
    """Provides capabilities for executing build and test commands."""

    async def run_build(self, target: str, config: ToolExecutionConfig) -> BuildOutput:
        """Executes a build command for a specified target."""
        ...

    async def run_tests(self, target: str, config: ToolExecutionConfig) -> TestOutput:
        """Executes test commands for a specified target."""
        ...


@runtime_checkable
class EnvironmentTool(Protocol):
    """Provides capabilities for inspecting the execution environment."""

    async def inspect_environment(self, config: ToolExecutionConfig) -> EnvironmentInfo:
        """Retrieves information about the current environment."""
        ...


@runtime_checkable
class WebTool(Protocol):
    """Provides capabilities for web browsing and searching (optional)."""

    async def browse_url(self, url: str, config: ToolExecutionConfig) -> WebContent:
        """Navigates to a URL and retrieves its content."""
        ...

    async def search_web(self, query: str, config: ToolExecutionConfig) -> list[SearchResult]:
        """Performs a web search."""
        ...
```

## Data Models

These dataclasses define the structured inputs and outputs for the coding tool protocols.

```python
# loom_ai/models_provider.py
from dataclasses import dataclass, field
from typing import Any, Optional
from pathlib import Path
from datetime import datetime


@dataclass(frozen=True)
class PermissionPolicy:
    """Defines permissions for tool execution."""
    allow_read: bool = False
    allow_write: bool = False
    allow_network: bool = False
    allow_subprocess: bool = False
    approved_paths: list[Path] = field(default_factory=list)


@dataclass(frozen=True)
class ResourceLimits:
    """Defines resource limits for subprocess execution."""
    cpu_time_seconds: Optional[float] = None  # CPU time limit in seconds
    memory_mb: Optional[int] = None           # Memory limit in MB
    max_processes: Optional[int] = None       # Maximum number of child processes


@dataclass(frozen=True)
class ToolExecutionConfig:
    """Configuration for a single tool operation."""
    timeout_seconds: Optional[float] = None
    working_directory: Optional[Path] = None
    permissions: PermissionPolicy = field(default_factory=PermissionPolicy)
    resource_limits: ResourceLimits = field(default_factory=ResourceLimits)
    workspace_id: str = "default" # Identifier for the isolated workspace


@dataclass(frozen=True)
class ToolError(Exception):
    """Structured error for tool failures."""
    type: str
    message: str
    details: Optional[dict[str, Any]] = None

    def __str__(self) -> str:
        return f"ToolError({self.type}): {self.message}"


@dataclass(frozen=True)
class ToolResult:
    """Generic result for operations that primarily report status."""
    success: bool
    stdout: str = ""
    stderr: str = ""
    exit_code: Optional[int] = None
    error: Optional[ToolError] = None


@dataclass(frozen=True)
class FileContent:
    """Result for file read operations."""
    path: Path
    content: str


@dataclass(frozen=True)
class FileInfo:
    """Information about a file or directory."""
    path: Path
    is_directory: bool
    size: Optional[int] = None
    last_modified: Optional[datetime] = None


@dataclass(frozen=True)
class TextEdit:
    """Represents a text edit operation."""
    start_line: int      # 0-indexed
    start_column: int    # 0-indexed
    end_line: int        # 0-indexed
    end_column: int      # 0-indexed
    new_text: str


@dataclass(frozen=True)
class ShellOutput:
    """Result for shell command execution."""
    stdout: str
    stderr: str
    exit_code: int
    success: bool


@dataclass(frozen=True)
class GitStatus:
    """Result for Git status operation."""
    staged: list[str]
    unstaged: list[str]
    untracked: list[str]
    current_branch: str
    remote_url: Optional[str] = None


@dataclass(frozen=True)
class GitDiff:
    """Result for Git diff operation."""
    diff_text: str


@dataclass(frozen=True)
class GitCommit:
    """Represents a single Git commit."""
    hash: str
    author: str
    message: str
    timestamp: datetime


@dataclass(frozen=True)
class GitLog:
    """Result for Git log operation."""
    commits: list[GitCommit]


@dataclass(frozen=True)
class BuildOutput:
    """Result for build command execution."""
    stdout: str
    stderr: str
    exit_code: int
    success: bool
    artifacts: Optional[list[Path]] = None


@dataclass(frozen=True)
class TestResult:
    """Details for a single test case."""
    name: str
    status: str  # e.g., "passed", "failed", "skipped"
    duration_seconds: float
    details: Optional[str] = None


@dataclass(frozen=True)
class TestOutput:
    """Result for test command execution."""
    stdout: str
    stderr: str
    exit_code: int
    success: bool
    test_results: Optional[list[TestResult]] = None


@dataclass(frozen=True)
class EnvironmentInfo:
    """Information about the execution environment."""
    cwd: Path
    env_vars: dict[str, str]
    system_info: dict[str, Any] # e.g., OS, Python version


@dataclass(frozen=True)
class WebContent:
    """Result for web browsing operations."""
    url: str
    html_content: str
    text_content: Optional[str] = None
    screenshot_base64: Optional[str] = None # Base64 encoded image


@dataclass(frozen=True)
class SearchResult:
    """A single result from a web search."""
    title: str
    url: str
    snippet: str
```

## In-Memory Implementation Strategy

An in-memory backend for these coding tools will primarily leverage standard Python libraries and `asyncio.subprocess` for external process execution.

*   **`InMemoryFileSystemTool`**: Will use `pathlib` for file and directory operations. For isolation and path traversal protection, it will operate within a designated temporary directory (e.g., created with `tempfile.TemporaryDirectory`) for each `workspace_id`. Permissions will be enforced by checking `PermissionPolicy` against requested operations and paths.
*   **`InMemoryShellTool`**: Will use `asyncio.subprocess.create_subprocess_shell` or `create_subprocess_exec` to run commands. `ToolExecutionConfig` parameters like `timeout_seconds`, `working_directory`, `permissions` (e.g., `allow_subprocess`), and `resource_limits` will be directly mapped to `subprocess` arguments or enforced via process monitoring.
*   **`InMemoryGitTool`**: Will execute `git` commands via `asyncio.subprocess` within the designated workspace directory. Parsers will be implemented to convert `git` command line output into the structured `GitStatus`, `GitDiff`, and `GitLog` data models.
*   **`InMemoryBuildTool`**: Will execute common build/test commands (e.g., `make`, `npm test`, `pytest`) using `asyncio.subprocess`, capturing stdout/stderr and exit codes.
*   **`InMemoryEnvironmentTool`**: Will gather information using `os`, `platform`, and `sys` modules.
*   **`InMemoryWebTool`**: Will use an asynchronous HTTP client (e.g., `httpx`) for `browse_url` and potentially a simple HTML parser (e.g., `BeautifulSoup4` if allowed as a lightweight dependency, otherwise regex-based parsing) to extract `text_content`. Web search could integrate with a public search API or a mock implementation.

A central `SandboxManager` component will be responsible for creating and managing isolated `workspace_id` directories, enforcing `PermissionPolicy` and `ResourceLimits` across all tool invocations, and handling `ToolError` exceptions.

8.  **Error Handling and Reporting**: Standardize the raising and catching of `ToolError` across all implementations.
9.  **Integration with `AgentLoop` / `RecipeExecutor`**: Define how agents will discover and invoke these tools within the existing Loom framework.
